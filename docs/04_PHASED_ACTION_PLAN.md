# خطة العمل المرحلية لتنفيذ منصة درب للكتب التفاعلية

## القواعد الحاكمة للتنفيذ (تُطبق في جميع المراحل)

1. **ثبات المخطوطات المرجعية:** يُحظر تعديل `docs/01_DARB_ANATOMICAL_BOOK.md` و`docs/02_DARB_EPIC_STORY.md` في أي مرحلة.
2. **المرونة وقابلية التعديل الشاملة (`No Hardcoding`):** كل النصوص العامة، أقسام الصفحة الرئيسية، التصنيفات (الأعمار، المستويات، التخصصات، أنواع الكتب)، الأدوار والصلاحيات، إعدادات المنصة، وقوائم المراجعة تُخزّن وتُدار ديناميكياً من قاعدة البيانات ولوحة التحكم.
3. **استمرارية البوابة الحالية:** تبقى النسخة الحالية (`darb-books`) عاملة وقابلة للنشر أثناء بناء الطبقات الجديدة.
4. **انضباط سير العمل مع Antigravity:** يشرح Antigravity خطته التفصيلية لكل مرحلة قبل تعديل أي ملف، ولا ينفذ `git commit` أو `git push` أو النشر إلا بعد مراجعتك وموافقتك الصريحة.

## تفصيل المراحل ومعايير القبول

### المرحلة 0: التوثيق وهيكلة الـ Monorepo
* **المخرجات:**
  * حفظ الوثائق الجديدة في `docs/`.
  * استخلاص محرك العرض الحالي إلى `packages/book-engine` وتعريف المخطط القابل للتمديد في `packages/book-schema`.
  * الحفاظ على تشغيل البوابة الحالية عبر `apps/web` مع نجاح `tsc --noEmit` و`vite build`.
* **معيار القبول:** البوابة الحالية تعمل بنفس السلوك السابق عبر `npm run preview` دون أخطاء `Console` أو تعطل في الصوت والفيديو والـ `3D`.

### المرحلة 1: النواة الخلفية والتصنيفات والهوية المرنة (`Backend + DB + Dynamic RBAC + R2`)
* **المخرجات:**
  * إعداد `apps/api` (`Fastify + TypeScript`) و`PostgreSQL + Prisma`.
  * بناء جدول `taxonomies` لإدارة الفئات العمرية، المستويات (من التمهيدي إلى البروفيسوراه)، التخصصات، وأنواع الكتب ديناميكياً.
  * بناء `Dynamic RBAC` يسمح بإنشاء أدوار مخصصة وربطها بالصلاحيات، مع تسجيل كل التعديلات في `audit_logs`.
  * بناء `system_configs` و`cms_sections` لإدارة إعدادات المنصة ومحتوى الصفحة الرئيسية.
  * ربط `Cloudflare R2` وترحيل الكتابين الحاليين (`epic-v1` و`anatomical-book`) كنسخ أولى (`book_versions`) مع دعم `Range 206`.
* **معيار القبول:** اختبارات آلية تغطي تعديل التصنيفات، إنشاء دور مخصص، التحقق من المصادقة، وقراءة الكتابين من `API` + `R2`.

### المرحلة 2: البوابة الديناميكية والمكتبة ولوحة التحكم (`Dynamic Portal + CMS + Control Plane`)
* **المخرجات:**
  * **الصفحة الرئيسية القابلة للتحرير:** تقرأ أقسامها (المميزات، الإمكانيات، دليل الاستخدام، الأخبار) وتنسيقات الهوية (`Branding/Theme`) من قاعدة البيانات.
  * **شاشة التهيئة لأول دخول والإعدادات:** اختيار وتعديل المستوى التعليمي والتخصصات المفضلة من التصنيفات الديناميكية الفعّالة.
  * **المكتبة المخصصة:** تصفية عمرية إلزامية + ترتيب وتخصيص حسب المستوى والمفضلات + بحث عربي مطبّع.
  * **لوحة التحكم المركزية:** واجهة شاملة لتعديل أقسام الصفحة الرئيسية، الأخبار، التصنيفات، الإعدادات والهوية، المستخدمين والأدوار، ومشاهدة سجل التدقيق.
* **معيار القبول:** إمكانية تعديل عنوان قسم في الرئيسية أو إضافة تخصص جديد من لوحة التحكم وظهوره فوراً في الواجهة والمكتبة دون إعادة بناء الكود.

### المرحلة 3: سجل المحولات وبوابة النشر والملكية الفكرية (`Pluggable Ingestion & Versioning`)
* **المخرجات:**
  * بناء `packages/parsers` بنظام `Parser Registry` لاستيعاب القالب القياسي والصيغ المتعددة (`Template ZIP`, `JSON`, `Markdown`, `DOCX`, `EPUB`) وتحويلها إلى `Canonical Book Schema`.
  * بوابة المؤلف لتحميل القالب، رفع أو تعديل الكتاب كإصدار جديد (`book_versions`) دون التأثير على الإصدار المنشور، ومعاينته في المحرك ثلاثي الأبعاد، وتوقيع إقرار الملكية الفكرية.
  * بوابة المراجعة (`CONTENT_REVIEWER`) بقائمة تحقق مرنة (قابلة للتعديل من الإدارة) لتوثيق المحتوى وحقوق النشر قبل تفعيل النشر.
* **معيار القبول:** رفع كتاب وتحديثه إلى إصدار ثانٍ مع بقاء الإصدار الأول منشوراً حتى اعتماد المراجعة، وتسجيل كافة القرارات في `audit_logs`.

### المرحلة 4: المحرك الغامر وسجل الكتل التفاعلية (`Extensible Interactive Block Registry`)
* **المخرجات:**
  * تطوير `packages/book-engine` ليدعم تسجيل مكونات تفاعلية (`Block Plugins`) تُحقن في النشرات أو تفتح بوضع ملء الشاشة (`Fullscreen Lab`) مع الحفاظ على صفر شريط تمرير رأسي.
  * بناء الكتل الأساسية (`model3d`, `simulation`, `geo_timeline`, `literacy_quran`, `code_sandbox`, `story_magazine`) بحيث تتشكل واجهتها ومحتواها من بيانات `JSON` المرنة.
  * تحديث القالب القياسي وإضافة كتاب تجريبي يعرض التفاعل عبر مستويات وتخصصات متنوعة.
* **معيار القبول:** إضافة كتلة تفاعلية جديدة عبر تعريفها في السجل وملف الكتاب تعمل بسلاسة على الحاسوب والجوال دون أخطاء `WebGL`.
