# وثيقة المعمارية الشاملة ونموذج البيانات لمنصة درب للكتب التفاعلية

> **ملاحظة تنظيمية:** هذه الوثيقة مرجع معماري وتصميمي جديد للمرحلة القادمة من مشروع `darb-books`، ولا تعدّل أو تستبدل المخطوطات المرجعية الثابتة (`01_DARB_ANATOMICAL_BOOK.md` و`02_DARB_EPIC_STORY.md`).

## 1. المبدأ المعماري الحاكم: المرونة وقابلية التعديل الشاملة (`Config-Driven & Extensible`)

تُبنى المنصة بحيث **لا يُقفل أي عنصر جوهري داخل الكود الجامد (`No Hardcoding`)**، وذلك عبر 6 ركائز مرونة أساسية:

1. **تصنيفات ديناميكية (`Dynamic Taxonomies`):** الفئات العمرية، المستويات التعليمية، التخصصات العلمية والأدبية، وأنواع الكتب تُدار من قاعدة البيانات (إضافة، تعديل، إعادة ترتيب، تفعيل/تعطيل) دون الحاجة لتعديل الكود أو إعادة النشر.
2. **واجهة وصفحة رئيسية قابلة للتحرير (`Dynamic CMS Sections`):** كل أقسام الصفحة الرئيسية (الترحيب، المميزات، الإمكانيات، طريقة الاستخدام، القوائم، التذييل، والأخبار) تُدار من لوحة التحكم مع إمكانية تعديل النصوص والوسائط والترتيب وإظهار/إخفاء أي قسم.
3. **تهيئة وهوية بصرية ديناميكية (`Dynamic Configs & Feature Flags`):** اسم المنصة، الشعارات، الألوان، الثيمات، سياسات التسجيل والتحقق، الصيغ المسموحة، وحدود الرفع تُضبط مركزياً من لوحة التحكم وتنعكس فوراً.
4. **أدوار وصلاحيات مرنة (`Dynamic RBAC`):** إمكانية إنشاء أدوار مخصصة جديدة وتجميع الصلاحيات الدقيقة فيها حسب حاجة الإدارة، وليس الاقتصار على أدوار ثابتة.
5. **محولات صيغ وقوائم مراجعة قابلة للتوسيع (`Pluggable Parsers & Checklists`):** نظام تسجيل للمحولات (`Parser Registry`) يقبل إضافة صيغ ملفات جديدة، وقوائم تحقق للمراجعة قابلة للتعديل من الإدارة.
6. **إصدارات غير هدامة للكتب (`Non-Destructive Versioning`):** إمكانية تعديل أي كتاب أو بياناته أو وسائطه وإرسال نسخة محدثة (`v2`) للمراجعة بينما تبقى النسخة المعتمدة (`v1`) متاحة للقراء حتى اعتماد التحديث.

## 2. المكدس التقني الموحد (`Unified TypeScript Stack`)

| الطبقة | التقنية المعتمدة | الدور والمسؤولية |
| :--- | :--- | :--- |
| **الواجهة والمحرك** | `Vite` + `React` + `TypeScript` + `Three.js` | الصفحة الرئيسية الديناميكية، المكتبة، الإعدادات، لوحة التحكم، ونواة القارئ ثلاثي الأبعاد |
| **الخادم الخلفي (`API`)** | `Node.js` + `Fastify` (أو `NestJS`) + `TypeScript` | واجهات البرمجة `REST/JSON`، المصادقة، `Dynamic RBAC`، الـ `CMS`، وبوابة الرفع والمراجعة |
| **قاعدة البيانات المركزية** | `PostgreSQL` + `Prisma ORM` | تخزين المستخدمين، التصنيفات الديناميكية، أقسام الصفحة، التهيئة، الكتب، الإصدارات، وسجل التدقيق |
| **تخزين الوسائط والملفات** | `Cloudflare R2` (متوافق مع `S3`) | استضافة ملفات `MP3` و`MP4` والصور ومجسمات `GLB/GLTF` والقوالب مع دعم `Range 206` |
| **معالجة الصيغ والوسائط** | `Worker` خلفي عبر `Parser Registry` | تحويل الصيغ المرفوعة (`Template ZIP`, `DOCX`, `MD`, `EPUB`, `JSON`, `PDF`) إلى `Canonical Book Schema` |
| **الحماية والجلسات** | `JWT` + `Refresh Tokens` (`HttpOnly Cookies`) | مصادقة آمنة، تحقق مرن (بريد/رمز/اعتماد إداري)، وحماية مسارات الـ `API` |

## 3. هيكلة المشروع (`Monorepo Architecture`)

```text
darb-books/
├── docs/                          # الوثائق المرجعية الثابتة + وثائق المعمارية الجديدة
├── apps/
│   ├── web/                       # تطبيق الويب (الرئيسية الديناميكية، المكتبة، القارئ، لوحة التحكم، الإعدادات)
│   └── api/                       # الخادم الخلفي (Auth, Dynamic RBAC, Taxonomies, CMS, Ingestion, Moderation)
├── packages/
│   ├── book-engine/               # نواة المحرك ثلاثي الأبعاد + سجل الكتل التفاعلية (Block Registry)
│   ├── book-schema/               # تعريفات TypeScript وZod المشتركة القابلة للتمديد
│   └── parsers/                   # سجل محولات الصيغ القابل للتوسيع (Pluggable Parser Adapters)
└── infra/                         # إعدادات Docker المحلية، Prisma migrations، وسكربتات التهيئة
```

## 4. منظومة الهوية والصلاحيات والمسؤوليات (`Dynamic IAM & RBAC`)

### أ. دورة المستخدم والتخصيص المرن
1. **التسجيل والتحقق:** تسجيل مرن يخضع لسياسة المنصة المُعدّة من الإدارة (تفعيل فوري، تحقق بالبريد، أو موافقة إدارية).
2. **التهيئة عند أول دخول (`First-Login Onboarding`):** يختار المستخدم قيمه من **التصنيفات الديناميكية الفعّالة** في قاعدة البيانات:
   * **الفئة العمرية (`ageGroup`):** تُدار ديناميكياً من جدول التصنيفات.
   * **المستوى التعليمي (`educationLevel`):** من التمهيدي حتى البروفيسوراه والتعليم التقني والقراءة العامة (قابل للتعديل من الإدارة).
   * **المفضلات والتخصصات (`preferences`):** التخصصات والقصص والروايات والمجلات (قابلة للتعديل من الإدارة ومن إعدادات المستخدم لاحقاً).
3. **قاعدة الوصول في المكتبة:**
   * **قيد الأمان العمري (إلزامي):** لا تظهر للمستخدم كتب تتجاوز فئته العمرية.
   * **التخصيص والمرونة:** تُبرز المكتبة الكتب المطابقة لمستواه ومفضلاته، مع إتاحة التصفح الحر لبقية التصنيفات المسموح بها لعمره وتعديل تفضيلاته في أي وقت.

### ب. مصفوفة الأدوار الافتراضية (قابلة للتعديل وإضافة أدوار مخصصة)

| الدور الافتراضي | المسؤوليات الأساسية | الصلاحيات الحصرية |
| :--- | :--- | :--- |
| **`SUPER_ADMIN`** | الإدارة العليا والتحكم المركزي الكامل | تعديل التهيئة والهوية، إنشاء/تعديل الأدوار والصلاحيات، إدارة التصنيفات، وتفعيل/تعطيل الميزات |
| **`PLATFORM_ADMIN`** | إدارة التشغيل والمحتوى العام | تحرير أقسام الصفحة الرئيسية، الأخبار، المستخدمين، وقوائم المراجعة |
| **`CONTENT_REVIEWER`** | مراجع علمي ومدقق ملكية فكرية | فحص الكتب المرفوعة، توثيق الصحة العلمية وحقوق النشر، اعتماد النشر أو طلب التعديل أو الرفض |
| **`AUTHOR`** | مؤلف / ناشر / أستاذ | تحميل القوالب، رفع وتحديث إصدارات الكتب، متابعة المراجعة، والرد على الملاحظات |
| **`LEARNER`** | قارئ / طالب / باحث | تصفح المكتبة، استخدام المحرك والمختبرات، حفظ التقدم والإشارات، وتعديل التفضيلات |

| **`system_configs`** | `key`, `value_json`, `category` (`branding`/`auth`/`uploads`/`features`), `updated_by`, `updated_at` | التهيئة المركزية والهوية البصرية ومفاتيح الميزات |
| **`cms_pages` & `cms_sections`** | `id`, `page_slug`, `section_key`, `title`, `content_json`, `sort_order`, `is_visible`, `updated_at` | تحرير الصفحة الرئيسية وصفحات التعريف والدليل ديناميكياً |

## 6. خط استيعاب القوالب والصيغ وبوابة النشر (`Ingestion & Moderation`)

1. **سجل محولات مرن (`Pluggable Parser Registry`):** تتعرف المنصة على الصيغة المرفوعة (`Template ZIP`, `JSON`, `Markdown`, `DOCX`, `EPUB`, `PDF` منظم) وتمررها عبر المحوّل المناسب لإنتاج `Canonical Book Schema` دون المساس بالمحرك الأساسي عند إضافة صيغة جديدة.
2. **قوالب قابلة للتحديث:** القالب القياسي الذي يحمله الكاتب يُدار كحزمة مرجعية قابلة للتحديث من الإدارة مع أمثلة لكل تخصص ومستوى.
3. **دورة المراجعة والملكية الفكرية:**
   `Draft (مسودة)` → `Submitted (إقرار ملكية فكرية)` → `Under Review (قائمة تحقق مرنة للمحتوى وحقوق النشر)` → `Changes Requested (مرتجع بملاحظات)` أو `Published (تفعيل active_version_id)` أو `Rejected`.

## 7. محرك العرض الغامر وسجل الكتل التفاعلية (`Extensible Block Registry`)

يُبنى المحرك بحيث يعمل بنظام **إضافات مسجّلة (`Block Plugins`)**؛ كل كتلة تمتلك معرّف نوع، ومخطط بيانات (`Zod Schema`)، ومكوّن عرض (`Renderer`) داخل الصفحة أو في وضع المختبر الكامل (`Fullscreen Lab`):

| نوع الكتلة (`Block Type`) | الوظيفة التقنية | قابلية التوسيع |
| :--- | :--- | :--- |
| **`model3d`** | عارض `Three.js` لملفات `GLB/GLTF` بالتدوير والتفكيك ونقاط الشرح | يدعم أي مجسم طبي أو هندسي أو كيميائي جديد عبر بيانات JSON فقط |
| **`simulation`** | لوحة محاكاة قائمة على معاملات قابلة للتعديل ورسوم بيانية | إضافة تجارب فيزيائية/كيميائية/رياضية جديدة بتعريف المعادلات والمعاملات |
| **`geo_timeline`** | خرائط تفاعلية بطبقات + خطوط زمنية | تحميل أي خريطة أو خط زمني تاريخي/جغرافي كبيانات |
| **`literacy_quran`** | مكونات للنطق، الإملاء، التشكيل، والتلاوة وأحكام التجويد | قوالب تمارين مرنة من التمهيدي حتى المستوى المتقدم |
| **`code_sandbox`** | محرر وتشغيل كود آمن داخل المتصفح | دعم لغات برمجة متعددة عبر تهيئة الكتلة |
| **`story_magazine`** | تخطيط مرن للسرد والقصص والروايات والمجلات | تبديل أنماط العرض والخطوط والوسائط من خصائص الكتاب |
